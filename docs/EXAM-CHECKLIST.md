# Проверка перед экзаменом

Этот список помогает проверить окружение и адаптацию. Требования и разметка, выданные на экзамене, имеют приоритет над примерами шаблона.

## Подготовительный час

- [ ] Уточнено, разрешено ли сохранять свой исходный каркас; доступность библиотек сама по себе не отвечает на этот вопрос.
- [ ] Go 1.22+, Node 22.12+ (22.x) либо 24.x, npm, Git и MySQL доступны в обычном терминале.
- [ ] На целевом Linux-компьютере выполнен `bash scripts/setup-online.sh`.
- [ ] `backend/vendor`, `frontend/node_modules`, `.offline/npm` остались на диске.
- [ ] Редактор открывает Go/TypeScript, расширения и инструменты языка установлены при интернете.
- [ ] Клиент MySQL/DBeaver подключается; все драйверы клиента скачаны.
- [ ] Создана БД, заполнен `backend/.env`; выполнены `migrate` и `seed-admin`.
- [ ] В браузере работают регистрация → вход → заявка → перезагрузка страницы.
- [ ] Проверены права администратора и изменение статуса.
- [ ] Интернет отключён: Go и Angular собираются и снова запускаются.
- [ ] Доступны локальные материалы, система сдачи/GitLab, «Автотест» и его документация.
- [ ] Открывается графический редактор; есть способ сохранить его исходный формат, обработать изображения и экспортировать макеты.

Не переносите `node_modules` с Windows в Linux. Если хотите перенести окружение между компьютерами, сначала проверьте одинаковые ОС/архитектуру и повторите сборку на каждом компьютере. Зафиксированные версии исходников и пакетов важнее «самых новых» обновлений перед экзаменом.

## Адаптация к варианту

- [ ] Название, поля и варианты значений совпадают с заданием.
- [ ] Логин/пароль администратора задаются через `.env`, его пользователь создан в БД.
- [ ] Все обязательные проверки выполняются и в Go, и в интерфейсе; ошибки видны рядом с формами.
- [ ] `data-testid` сверены с **выданным файлом разметки**, включая поля, кнопки, списки и статусы.
- [ ] Проверено требование к типу поля помещения: свободный текст, список или подсказки.
- [ ] Статусы и переходы между ними соответствуют варианту.
- [ ] Отзыв доступен в предусмотренном заданием состоянии заявки.
- [ ] Регистрация, вход, заявки, создание/редактирование и админка оформлены последовательно.
- [ ] Мобильный размер из задания проверен; для демонстрационного варианта — 390×844.
- [ ] Использованы предоставленные локальные изображения/шрифты, выполнена их обработка, сохранены исходники.
- [ ] ER-диаграмма соответствует **реальной** базе и связям `users → requests`, `users → sessions`.

## Функциональный прогон

- [ ] Регистрация: валидный пользователь создаётся; повторный логин и неверные значения дают понятную ошибку.
- [ ] Вход: неверный пароль отклоняется, после обновления страницы сессия сохраняется, выход завершает её.
- [ ] Заявки: пустой список, создание, редактирование, удаление и повторное открытие страницы работают.
- [ ] Второй пользователь не видит и не изменяет заявки первого, даже при подмене ID в API.
- [ ] Обычный пользователь не меняет статус через админский API.
- [ ] Администратор видит заявки и сохраняет статусы в MySQL.
- [ ] Отзыв до завершения отклоняется сервером; после завершения сохраняется.
- [ ] При недоступной БД/ошибке сервера интерфейс показывает ошибку, кнопки снова доступны.
- [ ] После `npm run build` собранный интерфейс работает на 8080, в том числе при прямом открытии вложенного URL.

## Что нужно доделать для полной сдачи

Каркас — стартовая база, а не все четыре выполненных модуля. Помимо адаптации приложения остаются:

- Исходники и экспорты дизайна в требуемом графическом редакторе.
- Обработанные изображения, шрифты и прочие материалы варианта.
- ER-диаграмма, выгрузка БД, документация/доступы в требуемом формате.
- Отдельный модуль API интернет-магазина: импорт в **другую БД**, `GET /orders`, фильтры, преобразование JSON и ошибки по точному контракту приложения к заданию.
- Прогон площадочного «Автотеста» и перенос контрольных сумм, если это предусмотрено.
- Сдача в репозиторий площадки и архивы. В демонстрационном КИМ используются `project_1.zip`, `layout_2.zip`, `project_3.zip`; проверьте имена и состав в своём варианте.

Сохраните SQL-дамп через клиент БД или `mysqldump`, проверьте его восстановление в отдельную тестовую БД. При подготовке архива проекта сохраните требуемую Git-историю; не смешивайте архив исходников с локальными паролями и кэшами. Если правила сдачи требуют доступы/офлайн-зависимости, передайте их предусмотренным способом и отдельно проверьте комплектность.

## Полезные команды

```bash
# Из корня, проверка офлайн-сборки
bash scripts/offline-check.sh

# Из backend, проверки Go без скачивания
GOPROXY=off GOTOOLCHAIN=local go test -mod=vendor ./...
GOPROXY=off GOTOOLCHAIN=local go vet -mod=vendor ./...

# Из frontend, сборка Angular
npm run build

# Из корня, что попадёт в коммит
git status --short
git diff
```

Перед новым коммитом сначала просмотрите изменения. Не добавляйте `.env`, пароли, cookie-файлы и диагностические дампы с чужими персональными данными в публичный GitHub.
